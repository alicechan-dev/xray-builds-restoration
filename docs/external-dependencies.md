# External Dependencies Audit

Historical snapshot: S.T.A.L.K.E.R. X-Ray Build 1935.

This audit covers external dependencies discovered from `xr_3da/XR_3DA.sln`, referenced `.vcproj` files, source includes, `#pragma comment(lib, ...)` directives, linked library fields, and explicit runtime DLL loading. It is documentation-only and is intended to guide a preservation-oriented CMake layer.

## Scope Notes

- **Engine-critical** means required by the main `XR_3DA` runtime solution or DLLs loaded by it.
- **Tool/editor-only** means present in the tree but not required for a first pass that builds and launches the game runtime.
- Some libraries are both vendored and referenced through old absolute paths. Prefer the vendored copy when it is complete and compatible.
- The original project files use MSVC 7.1 / Visual Studio .NET 2003 format. Several auxiliary editor projects also retain Borland C++ Builder assumptions.

## Highest-Risk Missing Or Partial Dependencies

1. **DirectX 9 SDK / D3DX9**: The engine includes DirectX 9 headers and links D3D/DInput/DXGUID. Modern Windows SDKs no longer ship D3DX9 in the same way.
2. **EAX SDK**: `eax.h` and `eax.lib` are referenced, but the SDK is not clearly present in-tree.
3. **OpenAL wrapper**: OpenAL source is present, but `wrap_oal.lib` is referenced by the sound DLL and was not found as a committed binary.
4. **Boost 1.30.x headers**: Luabind depends on Boost, but no Boost root was found.
5. **Lua public headers**: Lua internals are present under `xrLUA/src`, but the expected public `lua.h`/`lualib.h`/`lauxlib.h` were not found in that directory during this audit.
6. **Chilkat runtime DLLs**: Import libraries and headers are committed, but runtime DLLs were not found.
7. **`xrLauncher.dll`**: Loaded by the engine UI/launcher path, but no corresponding solution project was found in the main engine solution.

## CMake Migration Order Implications

1. Model Windows SDK and DirectX 9 dependencies first.
2. Build internal foundational targets: `xrCore`, `xrCDB`, `xrLUA`, `xrXMLParser`, `xrParticles`, `xrNetServer`.
3. Add vendored third-party static targets for ODE, Ogg, Vorbis, and GameSpy C sources.
4. Resolve EAX/OpenAL via imported variables or vendored OpenAL build before attempting `xrSound`.
5. Build `XR_3DA`, `xrGame`, `xrCPU_Pipe`, and `xrRender_R1`, then stage all runtime DLLs in one output directory.
6. Defer editors, old Borland projects, samples, 3ds Max plugins, DXT tools, QSlim viewers, and script IDE until the runtime launches.
